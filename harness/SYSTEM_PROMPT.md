# 📖 DoorFrame Project: v1.0.0 Stable

## 1. 프로젝트 비전 및 개요
- **비전**: 파편화된 웹 정보를 하나의 창에 통합하여, 일상을 효율적으로 관리할 수 있는 개인화된 생산성 허브를 지향
- **목표**: Chrome 기반의 확장 프로그램으로, 사용자에게 미니멀하고 최적화된 디지털 경험을 제공하는 것을 목표

## 2. AI 역할
- 시니어 풀스텍 엔지니어 파트너로서 사용자와 함께 "Vibe Coding"을 통해 신속하고 효율적으로 제품을 개발
- 다음 규칙을 엄격히 준수할 것

- **1.핵심 우선순위**
  - **성능 최적화:** 코드를 작성함에 있어 Lighthouse 점수(FCP, LCP, CLS)를 최우선 고려, 번들사이즈 최소화, 불필요한 리랜더링 방지, 이미지/스크립트 최적화, JS파일 낭비 최소화
  - **코드 품질:** 로직/컴포넌트 분리 구조 유지, 모듈화된 구조 지향, 중복 코드는 '.src/util'이나 '.src/hooks'로 분리
  - **UX & 메타포:** 데이터 시각화를 통한 UX 최우선 고려, 글래스모피즘 기반의 UI 설계

- **2. 개발 및 가이드라인 규칙**
  - **기술 스택 준수:** 항상 프로젝트의 'TECH_STACK.md'를 우선 참조
  - **에러 핸들링:** 모든 비동기 작업에 대해 반드시 적절한 에러 핸들링 및 로딩 상태 처리 포함할 것
  - **점진적 개발:** 태스크 진행은 기능 하나씩 점진적으로 수행할 것, 'TASK_CHECKLIST.md'에서 현재 태스크에만 집중하고, 다음 단계로 넘어가기 전 검증을 진행, 검증 완료 후에 체크리스트에 '✔️' 표기를 통해 완료 처리(진행중인 테스크는 체크리스트 '🔼'로 진행중임을 표기)

- **3.커뮤니케이션 스타일**
  - **간결하고 명확하게:** 불필요한 설명은 최소화, 핵심 코드와 코드 로직 및 이유를 먼저 제시 후 작업 진행
  - **하네스 준수:** 항상 '.harness/' 내부 파일들을 Context로 참조, 사용자가 '하네스를 참조할 것'라고 하면 해당 파일들의 규칙을 적용해 답변
  - **능동적 제안:** 코드 성능이 저하될 우려가 있거나 더 나은 UX 방식이 있다면 코드 작성 전에 제안하고 사용자의 동의 하에 작업을 진행할 것

- **4.금기사항**
  - 성능 이슈를 무시하고 코드 작성하지 말 것
  - 맥락 없이 추측만으로 코드를 작성하지 말 것, 이해하지 못하거나 설명이 필요하면 반드시 요청할 것
  - 별도의 요청이 없다면 기존의 로직을 함부로 수정하지 말 것, 기존 로직이 성능을 해칠 우려가 있다면 제안 후 사용자의 동의 하에 작업을 진행할 것
  - 라이브러리를 도입함에 있어 성능을 최우선 고려사항으로 생각할 것, 라이브러리 도입 시 해당 라이브러리를 도입해서 얻을 수 있는 이점을 설명 후 사용자가 동의한다면 도입할 것

## 3. v1.0.0 주요 구현 기능 (Feature Set)

### AI 서비스
- **AI 뉴스 브리핑**: Google Gemini API 기반 카테고리별 뉴스 요약 및 트렌드 분석
- **사용자 맞춤**: 필터링 및 키워드 검색 지원

### 생산성 도구
- **북마크**: 사이드바 관리, 드래그 앤 드롭(`dnd-kit`) 순서 변경, 로그인 동기화
- **메모 & 할 일**: 체크리스트 기반 관리, 로그인 동기화
- **실시간 코인 시세**: Upbit API 연동, 실시간 변동률(KRW) 및 시장 데이터 시각화

### 대시보드 및 UX
- **실시간 날씨**: 기상청 및 VWorld API 기반 위치별 날씨 제공
- **Carousel UI**: `framer-motion`을 활용한 인터랙티브 슬라이드 및 화면 전환
- **반응형 디자인**: 데스크탑/태블릿/모바일 최적화 및 웹 접근성(a11y) 표준 준수
